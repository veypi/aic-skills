# Design 设计台

先确定一句能指导取舍的设计北极星，再让结构、字体、色彩、素材和交互共同服务它。设计说明、可运行实样、可运行产品页面和评审报告是不同交付物，不互相冒充。

**主交互在对话框里。** 用户给出需求、现有代码或文件路径，Agent 直接修改项目，或创建自包含 HTML 后用 `page open` 打开；不要求用户建立私有设计项目，也不在 UI 中重复备注、方向选择等对话动作。

## 适用范围

- 新网站、App、后台、页面或组件的方向设计与 HTML 实样。
- 现有界面的视觉重塑、设计规范提炼、参考图或 URL 转设计契约。
- 用户明确要求的多方向比较、截图还原、只读视觉或 UX 评审。
- 将已经确认的实样实现到真实项目。

以下任务不要启动完整设计流程：

- 用户已点名元素和改法的小修改，例如改文案、删除指定元素、调整一处间距。
- 纯业务逻辑、接口、数据处理、无视觉变化的重构。
- 海报、PPT、视频、流程图、3D 等由其他专门技能承担的产物。

## 对话式任务路由

| 任务 | 直接交付路径 |
| --- | --- |
| 明确的小改动 | 修改目标文件，不做方向探索或独立评审 |
| 改造现有界面 | 读取相关页面、组件、设计变量与已有 `DESIGN.md`，保留业务行为，直接修改代码 |
| 新界面或整体 redesign | 锁定产品事实与方向，在用户选择的 `/fs` 位置创建自包含 HTML，`page open` 打开 |
| 明确比较多方向 | 共用同一真实内容制作多个 HTML 实样，直接打开比较；数量服从用户，未指定才默认三个 |
| 只读评审 | 只交付证据、诊断和建议，不修改产品文件 |
| 截图或 URL 精准还原 | 以参考为视觉基线，不重新发明方向；区分观察与推断 |
| 参考转可复用规范 | 读 `references/reference-contract.md`，先形成设计契约，再用于后续生成 |
| 实样转正式项目 | 使用项目已有框架、组件和 Token，不整段搬入实样代码 |

只有会改变核心方向且无法推断的信息才集中询问；其余作出可逆假设并标明。新 HTML 的保存位置不确定时先问，产物放用户选择的 `/fs` 位置，不写入技能安装目录。

## 主流程

### 1. 锁定交付与产品事实

写清用户、品牌、核心任务、真实内容、设备、已有素材、技术限制和交付物。现有项目先读相关页面、共享组件、设计变量和已有 `DESIGN.md`。规范冲突时列出冲突，按用户确认的优先级执行。

### 2. 拆参考，锁定主角与主动作

需要方向设计时读 `references/direction.md`。产品参考和交互参考分开：前者回答内容、构图和视觉身份，后者回答触发、对象变化、反馈和下一状态。每份参考记录“保留 / 改变 / 禁止复制”，没有真实证据就明确标注。

为首屏和关键状态各写一个唯一主角、一个唯一主动作，以及主动作后的可见结果。次要动作降级，不删判断所需的对象名称、状态和依据。

### 3. 收敛方向

默认只形成一个推荐方向。方向必须落到具体决定：北极星、概念来源、灰度骨架、字体、色值、主视觉、图标、控件语法、核心交互、记忆点、资产成本与放弃项。只有用户明确要求比较时才制作多个对外候选。

新界面先检查主视口灰度结构。主角、主动作或状态变化在灰度里分不清时，先改结构，不用颜色、字体或装饰遮盖问题。

### 4. 制作代表性实样

按任务需要读：

- `references/visual-language.md`：层级、排版、色彩、控件、图标和素材。
- `references/interaction-states.md`：状态、响应式、可访问性和动效。
- `references/proofroom-case.md`：本技能自身 UI 的视觉推导与对话式交付，不作为固定风格模板。

先做最能暴露方向优缺点的一页或核心流程，检查后再铺开。示例内容具体、自洽，不伪造真实业务成功、客户评价或产品指标。自包含 HTML 是可直接打开的设计实样，不把它当成正式工程架构。

在 ivec/vhtml 项目中实现时，项目规则与 vhtml 手册优先；不得为追求实样效果绕过框架契约。

### 5. 取得证据并评审

视觉结论必须基于目标视口的真实截图或可操作页面。不能看图或没有可运行环境时，明确“未验证实际视觉”或“未验证交互”，不打视觉分。

新界面、整体改版和整页以上润色按 `references/review.md` 进行一轮独立评审；宿主支持隔离执行时使用没有制作历史的执行者。小改动由主 Agent 检查即可。用户明确要求停止评审或不派生执行者时尊重其选择，并说明证据限制。只读评审交付报告后停止。

### 6. 对话迭代与沉淀

用户继续描述要改的对象、状态或方向，Agent 直接更新同一批文件并重新打开或刷新预览。出现无可见收益的反复横跳时保留最佳版本并停止。

交付说明写清选定方向及理由、实际改动、未完成项、动效、评审证据和验证限制。需要复用方向时更新 `DESIGN.md`；需要工程 Token 时同步 `tokens.css`，不让两份文件互相矛盾。

## AIC 原生工作方式

- 文件由 Agent 用 fs 工具读写；不建立私有项目库，不创建 `.design` 主存档。
- 新实样使用自包含 HTML；已有项目沿用其真实技术栈。通过 `page open` 或平台文件 opener 查看结果。
- 网页取证复用 `browser` 技能，原生应用检查复用 `cua`；本包不提供截图脚本或设备服务。
- 技能首页是展示与交接层：案例按钮把原始 Prompt 通过 `/?user_prompt=<编码后的文本>` 交回对话框，不在页面里执行生成。
- 独立概念或评审使用宿主的隔离/委派能力；没有能力或用户不要求时自行检查，并明确“未独立评审”。

## 实样画廊与主题工具

`ui/index.html` 提供需求输入、真实 HTML 实样、原始 Prompt 和主题 Token 工具。`ui/cases/cases.json` 是案例清单，同目录每个 id 对应一个可直接打开的 `<id>.html`。

**本技能自己的 UI 是方法的第一案例，不豁免上述主流程。** 方法与实例必须同步：先锁定真实对象、主角和主动作，再写页面；不能用通用后台、说明文字或评审流程代替设计本身。

案例先由产品对象和灰度骨架形成差异，再决定字体、色彩与素材。不要从色板、几何装饰或既有案例换皮开始。

新增案例必须：

- 有真实可运行 HTML，不用截图或装饰占位冒充实样。
- **上架前有真实视觉证据**：至少检查画廊使用的 960×600 设计视图和实际打开视口，取得当前版本截图或用户明确确认。没有视觉证据时可以保留为工作文件，但不加入 `cases.json`；静态测试不能代替视觉验收。
- 文字不重叠、不裁切，预览不出现内部滚动条；几何块、线条和素材都有明确的信息或构图职责。
- 只声明 HTML id 与可独立执行的原始 Prompt，不添加标题、标签或描述等界面注释。
- 与已有案例在灰度骨架、字体、色彩或主视觉上形成真实差异，不是换皮。
- 示例数据自洽且明确为示例，不伪造真实指标。
- 不依赖未授权外部素材；新增素材来源与许可写入 `NOTICE.md`。
- 发现不合格案例先撤下，不为数量或补齐网格而马上再做一个凑位。

`ui/theme.js` 从主色生成语义 Token，包含悬停、浅底、对比文本、画布、表面、正文、辅助与边框。它只提供设计起点，不代替项目现有 Token，也不强迫所有产品共用一种风格。

## 文件与模板

`templates/` 提供可复制的起点，不是必须全部生成的固定产物：

- `DESIGN.md`：设计契约。
- `tokens.css`：语义 Token。
- `direction.md`：方向卡。
- `review.md`：证据化评审报告。

需要持续维护设计规范时，把这些文件放在用户项目目录；不需要时不要为了形式创建。

## 验收

- 任务路由正确：现有项目直接改代码，新实样直接创建 HTML 并打开；没有 `.design` 项目机制。
- 方向决定具体、可执行，候选不是同一模板换皮。
- 技能自身 UI 与案例遵守同一套方法；案例上架有当前版本的视觉证据，坏案例不凑数。
- 案例可打开，原始 Prompt 可复制或交回对话框，主题 Token 有真实预览与测试。
- 没有真实画面时不声称视觉验收通过；独立评审不可用时明确说明。
- 技能包不包含用户项目、密钥、二进制或构建产物。
