# 发布（私有 → 广场）

> 面向"不了解平台实现"的 AI。目标：把私有包安全地发布出去，或分叉别人的包。

## 1. 两种形态

| | 私有行（工作区） | 公开行（广场） |
| --- | --- | --- |
| 存储 | `/skills/{id}/`（属主可读写） | `/skills/{id}/`（内容不可变） |
| 元数据 | frontmatter 实时生效 | 发布时冻结 |
| 数据 | 自己的运行库随改随生效 | 发布**不带数据**，公开库从空开始 |
| 更新 | 直接改文件 | 发新版本 |

同一 (owner, name) 的私有行与公开行是**两行**——工作区与发布物同名是常态。

## 2. 发布流程

1. 管理页 `/skills/detail/cloud/{id}` 发起，或
   `POST /api/skills/releases {source, name?, version}`（source = 私有行 id/name）。
2. 契约校验：frontmatter `name` 必须等于注册表行 name；内容按静态包校验路径、体积、元数据。
3. 打包：服务端流式打包私有行目录（**不含运行库**）；未压缩总量与最终 zip 大小各有 **16MiB 闸门**，任一超限都失败。
4. 审核：全量审核，SKILL.md 文本同样会被审。管理员自发布自动通过。
5. 通过 = 公开行落库 + 目录冻结（历史版本不可变留存）；拒绝 = 给备注，可重提，
   但**必须换一个尚未消耗的 version 值**（提交即消耗，被拒也算；建议按 SemVer 递增，运行时不做大小比较）。
6. 版本号规则：`^[A-Za-z0-9][A-Za-z0-9._-]{0,15}$`，禁连续点。

## 3. 发布前自查

- **界面**：有没有越权调平台接口、偷传数据、来路不明的脚本；资源与 API 用相对路径
  （或 `url_prefix` 前缀）；页内导航用相对页面名——**不写死技能 id、不手拼前缀**。
- **接口**：SQL 没有字符串拼接；`user_id = :user_id` 行级过滤齐全；全表拉取加了 LIMIT。
- **设备**：`cli/` 只有源码；服务声明里的程序路径跨平台可解析。
- **文本**：内容合规。
- **通用**：frontmatter 是严格 YAML 且 `name` 与注册表行一致；包体积达标；
  没有调试残留（`.bak`、临时文件、大素材、密钥、真实用户数据）。

## 4. 常见拒绝原因

1. `name` 与注册表行不一致，或名字不合规（`^[a-z0-9][a-z0-9-_]{0,31}$`）。
2. frontmatter 字段拼错（`desc` ≠ `description`）导致解析失败。
3. SQL 多语句 / DDL / 拼接 SQL / 缺 `user_id` 过滤。
4. 界面写死技能 id 或手拼前缀（fork / 换部署后 404）。
5. 包内塞大文件或无关二进制。
6. 内容违规或明显调试残留。

## 5. 发布后

- **验证**：换另一个账号 → 能在技能列表里搜到 → 打开 `/skills/cloud/{id}` →
  用 `curl` 读一遍数据面。
- **内容不可变**：没有编辑面，改动 = 发新版本。`description/nickname/keywords/icon`
  随新版本从 frontmatter 刷新（给了就覆盖，没给保持原值）。
- **数据不迁移**：公开库从空开始；需要带数据就用属主管理面导出/重建。
- **下架**：删行 + 包目录 + 全部历史版本 + 运行库，绑定关系级联清理，释放名称与名额；
  已安装设备不受影响。
- **分叉（fork）**：`POST /api/skills/{id}/copy` → 得到自己的私有副本（可改、可再发布）。

## 6. 给 AI 的提醒

发布是**独立动作**：建行 ≠ 写文件 ≠ 发布 ≠ 安装软件 ≠ 授权。
用户说"发出去"只做发布这一步；说"装到设备"是另一件事（且通常需要用户自己操作）。
发布前先把自查清单过一遍——被拒一次就要涨版本号重来。
