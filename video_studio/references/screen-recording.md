# 长录屏与原始视频素材处理

适用于屏幕录制、操作实录、长时间等待过程等产品视频。目标不是把源片剪成一组漂亮但断裂的片段，而是在保留真实操作的前提下压缩时间。

## 1. 先确认源片与叙事约束

1. 用 `ffprobe` 记录分辨率、帧率、时长、音轨，不以文件名或肉眼判断清晰度。
2. 先确认哪些操作必须完整保留。用户说“不要抽界面 / 不要剪掉操作”时，源片每个界面区间都必须出现在成片里，只允许变速。
3. 局部裁切、冷开场重复、跳过一个窗口切换，都是独立创作决定，不能默认使用；用户要求连续实录时全部禁用。
4. 原始素材只读，生成物写入项目 `assets/`。保留源路径、源区间、速度、实际输出时长与校验值。

## 2. 变速：连续 PTS 重定时，不用 select 抽帧

**禁止把 `select='not(mod(n,K))'` 当作默认加速方法。** 它按帧号稀疏采样，高倍速下鼠标、棋子和窗口操作会明显瞬移。

按源区间直接缩放时间戳：

```sh
ffmpeg -ss START -t DURATION -i source.mov \
  -vf "setpts=PTS/30" -r 60 -an \
  -c:v libx264 -preset medium -crf 17 -pix_fmt yuv420p part.mp4
```

- 30× 就写 `setpts=PTS/30`，3× 就写 `PTS/3`，不要再用帧号公式反推。
- 源片 60fps 时输出也优先 60fps；高倍速段会少显示一些中间状态，但采样由连续重定时和输出帧率统一处理，不额外制造稀疏抽帧。
- 每个区间的速度必须与角标一致。低倍速操作段不要为了赶总长擅自继续加速。

## 3. 连续内容不得留空洞

分段编码只是实现手段，不是删内容的许可。若分成多段，源区间必须首尾相接：

```text
0–516s @30×
516–558s @3×
558–736s @30×
736–744s @3×
744–1162s @60×
1162s–结尾 @6×
```

不得把中间“觉得不重要”的几十秒直接删掉。需要删除时必须得到用户明确同意。

## 4. 长 4K 录屏：分段编码，再无损拼接

多路 4K 输入同时做 filter/concat 可能占用大量内存并失败。长录屏优先逐段编码，再用相同编码参数无损拼接：

```sh
ffmpeg -f concat -safe 0 -i list.txt -c copy -movflags +faststart full-timeline.mp4
```

`list.txt`：

```text
file 'seg-1.mp4'
file 'seg-2.mp4'
file 'seg-3.mp4'
```

所有分段保持相同分辨率、fps、codec、pix_fmt。拼接后必须 `ffprobe` 全片并完整解码检查。

## 5. 清晰度：素材、逻辑画布、导出三者分开

- 逻辑画布可以是 1280×720，但素材仍应保留 3840×2160，导出时再栅格化到 4K。
- **720p 素材导出成 4K 只是放大，不是真 4K。** 源片是 4K 时，从源片重新生成 4K 素材。
- 局部特写受裁切区域原始像素限制；不要声称每个局部放大镜头都有原生 4K 细节。
- 导出 MP4 超过 1080p 时使用支持 4K 的 H.264 profile/level；当前技能使用 High 5.1（4K30 档）。4K60 导出前需确认浏览器编码配置支持，不能只看容器分辨率。

## 6. 用实际输出时长校准时间线

不要只用 `源时长 / 倍速` 估算成片时长。源片帧时间戳、起止包和拼接可能产生偏差。

1. 对每个输出段执行 `ffprobe format=duration`。
2. 依次累加得到真实区间起点。
3. 按真实起点设置倍速角标、标题、overlay 与 SFX。
4. 改过任何速度或区间后，重新计算所有后续时间，不沿用旧值。

## 7. 音频与加载体验

- 生成音乐用于浏览器预览时优先提供 MP3；FLAC 可保留为母版，但出现预览无声时先换成广泛兼容的 MP3 再排查。
- 不需要音效时删除 `sfx`，不要让突兀的模板音效盖过纯音乐。
- 打开大素材存档必须显示真实 loading 状态，不能在预载期间显示“未打开存档”。
- 干净存档的打开/返回不得触发写盘；外部 reload 前先取消待执行的旧自动保存。

## 8. 最低验收

- 全片解码无错误，分辨率/fps 与目标一致。
- 每个要求保留的操作至少有截帧证据；连续实录还要检查相邻区间边界。
- 倍速角标与实际区间一致。
- 音乐在预览中实际可听，导出后仍是同一音轨。
- 用户明确要求保留的内容没有因“优化节奏”被删除。
