# 扩展模型（三端）

> 面向"不了解平台实现"的 AI。目标：把一句需求翻译成"哪几端要动、各加什么内容物"。

## 1. 三个端

| | ☁️ 云端 | 🖥️ 界面 | ⌨️ 设备 |
|---|---|---|---|
| 负责 | 存储与服务 | 交互与呈现 | 执行 |
| 存什么 | 用户文件、技能包原始内容、每个包自己的数据表 | 云端固化（技能包文件、用户文件、桌面档案）＋ 页面缓存与临时（本地存储、页面本地文件） | 设备本机配置与状态（`~/.aic`、服务配置），内容从云端取 |
| 怎么说话 | HTTP 接口（同源，cookie 身份） | 页面指令（AI 直接操作页面）＋ 页面内事件 | 命令行（vsh）＋ 服务命令（MCP/TCP 等，复杂参数走 stdin） |
| 能加的东西 | 技能包（说明书/接口/表）、用户空间文件 | 界面（.html 页面或组件）、桌面档案规则 | 脚本、原生命令、常驻服务 |
| 谁消费 | 平台服务、页面、AI | 用户、AI | AI、用户 |

## 2. 需求 → 组合对照表

| 用户说的话 | 端 | 内容物 | 落位 | 生效 |
|---|---|---|---|---|
| 「给我做个界面」 | 界面 | `.html` | 技能包 `ui/` / 用户云空间 / 页面本地 | 装载 |
| 「做个能查数据的应用」 | 云端 + 界面 | 表 + `api/*.sqlx` + 页面 | 技能包 | 装载 |
| 「做成一个能给别人用的东西」 | 云端 | `SKILL.md`（+ 可选界面/接口） | 技能包 | 装载 → 审核发布 |
| 「把桌面的侧栏换成我的」 | 界面 | 档案规则（dock） | 用户云空间 `.profile/<name>.json` | reload / live |
| 「把某个组件换成另一个」 | 界面 | 档案规则（alias） | 同上 | reload |
| 「给这个组件的槽里放点自己的东西」 | 界面 | 档案规则（slot）＋ 纯结构片段 | 同上 | reload |
| 「桌面布局记下来」 | 界面 | 档案规则（layout） | 同上 | live |
| 「设备上要能跑一条命令」 | 设备 | 程序源码 / 脚本 | 设备本地 | 用户安装 |
| 「设备上要有个常驻服务」 | 设备 | 服务声明 + 源码 | 技能包 `cli/`（仅内建包会被注册） | 安装 / 启动 |
| 「每天定时帮我做 X」 | 云端 | 平台任务调度 | 平台 | 定时触发 |

## 3. 同一件东西常常跨端

分层说的是"谁负责什么"，不是"各存各的"：

- 技能包内容存**云端**，界面从云端加载它再与用户交互；
- 桌面档案存**云端**，作用在**界面**（装载层注册替换规则）；
- 设备命令装在**设备**上，说明书写在**云端**的包里；
- 页面里的数据来自**云端**接口，页面自己只在本地存缓存与临时。

所以"一个东西属于哪端"要按**它最终起作用的地方**判断，而不是按它存在的地方。

## 4. 判定速查

```text
关掉浏览器还在吗？        → 在 = 云端
用户看得见点得到吗？      → 是 = 界面
要动用户自己的电脑吗？    → 是 = 设备
要发布给别人吗？          → 是 = 云端（技能包）
要定时跑吗？              → 是 = 云端（任务调度）
只是自己先试试吗？        → 界面（页面本地）
```

## 5. 不算扩展的事

- 改平台自身的代码（那是平台开发）。
- 改会话里的临时状态（聊天草稿、窗口临时摆放）——那是运行时，不是产物。
- 给别的技能写说明——落点仍在技能包，只是改的是它的内容。

## 6. 组合的两种典型形态

**单端**：只要一个界面（界面层）、只要一条命令（设备层）、只要改桌面（界面层）。

**多端**：多数"应用"型需求都是三端一起——
云端建包（说明书 + 表 + 接口）→ 界面做页面 → 设备补命令。
判断标准：**功能是否需要"关掉浏览器还活着"或"动到用户自己的机器"**——是就多半要跨端。
