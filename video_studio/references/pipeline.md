# 制作流水线

从"做一个关于 X 的视频"到交付的完整流程。两种模式：

- **共同创作**（默认）：阶段 0–3 每阶段给用户确认，每轮只问 1–3 个最能减少返工的问题；用户确认业务与创意方向，AI 自主完成实现参数与技术 QA。
- **自主推进**：用户明确说"你全权决定/直接做"时，阶段 0–3 的判断记录在项目说明里连续执行，不逐阶段暂停。用户已有的明确要求始终是约束。

## 阶段 0 · 简报

写进项目目录 `brief.md`（fs 工具 _host=page）：
- 产品/主题是什么，给谁看，投放在哪（手机竖屏？发布会横屏？）→ 决定 size 与节奏
- 功能清单（P4）：逐一列出要展示的功能/信息点，后面每点映射镜头
- 素材盘点：用户能提供什么（截图/logo/录屏/音乐）；缺的列出来请用户上传
- 视觉基调：从产品自身的设计系统提取 tokens（字体/配色/圆角/间距），不另造一套不相干的"宣传片皮肤"
- 数据口径：哪些数据可以展示，敏感内容一律虚构脱敏
- 讲解策略：是否需要旁白、语气/称呼、哪些镜头必须靠旁白解释；需要时同步确定人声与 BGM 的主次

## 阶段 1 · 结构与能量曲线

- 全片 8–60s，每场景 3–6s；先排**能量曲线**再填镜头：开场（中，单主角 Q5）→ 铺垫爬升 → 高潮段 → 收尾峰值（Q8）或品牌静收
- 功能清单 → 镜头映射表：每个功能配一个镜头 + 选用的镜头卡（`shots/`）；一种手法全片只当一次主角（P4）
- 有 BGM 且强节奏：先 `win(id).analyze_music({src: 'assets/bgm.mp3'})`，读 beats.json，切点/重音钉真实拍点；confidence <0.3 先人工核对
- 产出分镜表写进 `brief.md`：每场景 = 时长 / 画面内容 / 镜头卡 / 运镜 / 字幕 / 旁白句 / SFX 预留 / hold 预算（R1/R3）

**共同创作在此暂停**：给用户看分镜表确认后再实现。

## 阶段 2 · 素材

- 长录屏、操作实录或需要选择性加速时，先读 `references/screen-recording.md`：连续 PTS 变速、不抽帧、不擅自删除操作、4K 分段编码、按实际输出时长校准。
- 真实页面截图（Q1）：用 browser/cua 技能截图，或把链接给用户请其截图上传「素材」tab
- 外部素材：把下载链接发给用户，请其下载后上传素材面板（page curl 不能下载外部素材）
- 素材命名语义化（assets/hero-card.png），分辨率按显示尺寸 2x（Q2，运镜镜头按推近后算）
- TTS 配音：画面主体完成后逐场景生成一段话。把播放头置于该场景，`win(id).gen_voice({text: '本幕讲解', name: 'voice-s1', set: 'voice'})` 自动写入 scene.voice；每幕单独试听，产品名/数字/单位必须核对

## 阶段 3 · 逐场景实现

- `win(id).new_video({path: '/fs/.../demo.video_studio'})` 建存档 → 写主 `.video_studio`（场景多时拆分 scenes/scene_N.json）→ `win(id).reload_video()`
- 每场景按镜头卡 recipe 写元素/关键帧/运镜；先读 `shots/` 对应卡全文再写，不凭卡名瞎编
- 写完一个场景就截入场/动作/hold 三个关键帧并 fs.read 自检（P1），再写下一个；可疑处看全尺寸单帧，不只看缩略拼图
- 坐标基于 size 布局不越界；文字框给足高度；有效字高按 Q11 验收；中心线、复合图标和轨道标签按 Q12/Q13 验收
- 每场景末留 hold（R1）：关键帧末段平直 ≥1s 或 duration 富余

## 阶段 4 · 声音（画面锁定后，S3）

- 读 `sound-design.md`：无旁白时 BGM 音量 0.2–0.35 垫底；有人声时降到 0.15–0.20，SFX 逐条钉 t + note 并避开关键字
- 配音对齐：scene.voice.offset 是本幕内秒数；每幕必须满足 duration + offset ≤ scene.duration。需要更多时间时只延长本幕 hold 或调整本幕动画，再重钉后续 SFX，不用一条长旁白驱动全片
- 卡拍片：sfx 的 t 钉 beats/onsets 真实秒数；全画面冲击 ≤3 处（R4）

## 阶段 5 · 整片自检

- `run_video` 播放确认节奏并整片审听旁白/音乐/音效；逐场景 shot_video 抽帧检查，做一张全场景 hold 帧总览拼图
- 对照 `aesthetic-rules.md` 逐条自检，输出 `编号 ✓/✗(位置)`；按 final-review.md 跑全帧 buildFrame 技术回归
- 改过时长/顺序 → sfx 全表重钉（S3）

## 阶段 6 · 独立终检 + 交付

- 按 `final-review.md` 派干净上下文 subagent 终检（delegate），首检不交给用户（P1）
- 终检通过 → 向用户总结（时长/场景数/亮点），提醒点顶部「导出」按钮自行导出
- 导出由用户操作，AI 不触发
