# 自我样例：校样视觉与对话式画廊

本文记录 `design` 技能自身 UI 的设计推导。它不是一套要求所有项目复制的“校样风格”，而是一份方法与实例必须一致的案例：技能教别人怎样做设计，就要先让自己的界面经得起同一套追问。

## 1. 产品事实

- 用户的主要工作发生在对话框：提供现有代码或一句需求，让 Agent 直接修改项目，或创建 HTML 后打开。
- 技能首页首先证明“它能做出什么样的设计”，然后帮助用户把方向交回对话框。
- 首页的真实对象是可运行实样、原始 Prompt 与主题 Token，不是项目档案。
- 这个 UI 同时是能力样例。通用后台模板即使功能正确，也不能证明设计能力。
- 技术约束：vhtml、平台明暗主题与 Token、真实 HTML 文件，不依赖外部装饰素材。

由此得到两个目标：**可运行实样是唯一主角；从看到方向到发给 AI 只能有一个明显动作。**

## 2. 被拒绝的三种做法

### 通用管理后台

侧栏导航、圆角按钮组、统一 14px 文本、最近项目表都能快速搭建，但它们回答的是“怎样放一个后台”，不是“怎样开始一次设计”。文件管理喧宾夺主，界面没有自己的立场。

### 设计方法展板

把 brief、北极星、字体、色值和流程说明放在首屏，看似重视方法，实际把交接文档误当产品。方法应该决定界面的形状，不应该占据界面替自己辩解。

### 私有项目中转站

要求用户先创建主存档，再在页面里写备注、选方向，最后回写选择，会把本可在一次对话里完成的动作拆成两套交互。对“直接改现有代码”和“生成 HTML 打开”两类主任务都是多余门槛。

## 3. 概念来源：校样与作品索引

保留“校样室”的视觉概念，但不再围绕它制造项目管理器：

- 首页是**设计事务所的作品索引**，不是文件列表。
- 每个案例是**可打开的设计实样**；画面是唯一主角，卡片不展示名称、编号、标签或描述，id 只负责文件寻址。
- 原始 Prompt 是实样的**制作底稿**，在悬浮或聚焦遮罩中直接阅读，也可一键交给 AI。
- 主题工具是**调色与语义 Token 台**，结果直接进入设计需求。
- “发给 AI →”把用户送回对话框，页面本身不执行生成。

概念不是给界面加一个名字。它必须同时改变对象、动作、排版和状态表达。

## 4. 灰度结构

### 对话入口

```text
Design                                  查看实样  开始设计 →
01
从一句话，到好界面。          你想设计什么？
                             ____________________
                             输入真实需求……
                             发给 AI →
```

首屏同时说清产品能力与交付方式。不是宣传 Hero 加装饰图，而是把一句需求直接放在第一视觉层级。

### 实样画廊

```text
02  实样
┌────────────────────┐      ┌────────────────────┐
│   真实 HTML 实样   │      │   真实 HTML 实样   │
│                    │      │                    │
│ 悬浮 / 聚焦：      │      │ 悬浮 / 聚焦：      │
│ HTML 地址          │      │ HTML 地址          │
│ 原始 Prompt        │      │ 原始 Prompt        │
│ 打开页面  发给 AI  │      │ 打开页面  发给 AI  │
└────────────────────┘      └────────────────────┘
```

预览可直接打开；悬浮、键盘聚焦和触屏都能到达同一操作层。Prompt 在遮罩中直接显示，不再增加展开/收起交互。没有项目选择、备注、保存回写或最近记录。

### 主题工具与交付方式

主题工具左侧选择主色与明暗模式、生成 Token，右侧立即用这些 Token 呈现同一张测试页。工具之后不再附使用教学、三步流程或底部口号。

## 5. 字体是结构，不是收尾装饰

展示角色使用 `Iowan Old Style / Palatino Linotype / Songti SC / Noto Serif CJK SC` 的本地衬线回退链，操作与辅助信息使用平台无衬线：

- 展示标题、章节与工具预览保持克制，并按容器缩放；不用超大字号填补内容不足。
- 衬线标题建立“稿件与校样”的编辑语境。
- 小号无衬线操作文字保持工具精度，不把整页变成文章。
- 尺度差先承担层级，字重只做辅助。

这套字体选择来自“校样与作品索引”，不是所有产品都应使用衬线。换到交易终端、儿童产品或工业控制台，必须从各自对象重新推导。

## 6. 色彩、表面与控件

- 背景、正文、辅助、边框全部使用平台 Token，明暗主题共享同一结构。
- 强调色只用于当前动作、“发给 AI”和选中状态。
- 分隔线只保留导航、真实列表和实样边界；章节靠间距分组，输入区与工具区使用语义明确的表面。内容变多时不靠继续加线维持秩序。
- 主操作采用文字加下划线与箭头，像校对签署，不使用通用实心按钮。
- 实样内部可以拥有完全不同的色彩与控件语言，首页不为它们强行统一皮肤。

## 7. 对话交接是唯一主流程

- 需求输入为空时给出明确校验，不打开发空的对话。
- “创建 HTML”和“改造现有界面”只帮用户组织需求，最终仍由 Agent 读取、创建和打开文件。
- 案例操作只有打开页面和把原始 Prompt 发给 AI；没有隐藏的保存语义，也没有额外名称、描述与标签。
- 主题工具可以直接复制 Token，也可以连同需求一起交给 AI。
- `$os.open('/?user_prompt=…')` 是主交接路径；不可用时才退回新标签页。

## 8. 案例上架与自身约束

- `cases.json` 只保存 id 与原始 Prompt；案例多样性先体现在产品对象和灰度骨架，不靠换色或几何装饰凑数。
- 上架前检查 960×600 画廊视图与实际打开视口，必须有当前版本截图或用户明确确认；静态测试只证明文件与语法，不证明视觉质量。
- 标题溢出、文字重叠、内部滚动条和无信息职责的装饰都阻止上架。发现不合格案例先撤下，不为补齐网格马上再做一个。
- 正常打开案例或项目不弹成功提示；需要反馈时使用平台 `$message`，不在这套 UI 里另造通知组件。

## 9. 向 Video Studio 迁移，而不是复制皮肤

同一视觉语法可以迁移，但产品隐喻必须换成视频自己的对象：

- 项目索引变成**视频作品与实样索引**，大编号对应作品与实样，但不额外展示“片架”标题。
- 校样画面变成**舞台与胶片格**，而不是把视频场景叫设计方向。
- 校对色变成**播放、当前场景与导出**的少量强调。
- 细线和编辑排版服务时间轴的尺度与节奏，不删除高密度控制。
- 保留场景、预览、时间轴、素材和导出行为，不为了视觉统一重写引擎。

如果迁移后只是所有产品都变成衬线和细线，却损失了各自的对象与动作，就不是有效迁移。

## 10. 可迁移的方法

1. **先找一个能改变决定的产品隐喻。** 如果隐喻只改了标题，没有改对象和动作，它就没有生效。
2. **方法要体现在界面上，而不是写在界面上。** 删减、层级和主动性应该能被直接看见。
3. **字体与尺度属于灰度结构。** 不要先用统一正文拼完，再靠颜色和圆角制造层次。
4. **一个强观点胜过十种装饰。** 本例集中投入“实样索引”，主动放弃后台卡片、项目管理和宣传模块。
5. **首页不能替代 Agent。** 展示与工具要缩短对话交接，而不是另造一套生成和选择流程。
6. **响应式必须跟着容器。** 标题和控件尺度使用 `cqw` 与容器断点；实样按固定设计尺寸等比缩放，不能用 `vw` 或裁切内部滚动条冒充缩略图。
7. **案例不是新模板。** 下一次仍从产品事实开始；直接复制衬线和细线，正是本技能要反对的做法。
8. **视觉证据是案例准入条件。** 能运行、测试通过和看起来已完成是三件事；没有真实画面，不把案例放进画廊代表技能能力。
