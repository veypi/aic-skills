# 证据化评审

## 评审模式

| 场景 | 方式 |
| --- | --- |
| 新界面或整体改版 | 代表性页面完成后进行一轮独立视觉评审，可给 1–10 分并说明差距 |
| 已有界面整页以上润色 | 对照现状和既有规范评审，不强制打分 |
| 主要操作流程发生变化 | 增加一条核心 UX 路径走查，覆盖可观察结果与失败恢复 |
| 小改动 | 主 Agent 检查改动处和相邻区域，不另派评审 |
| 用户只要求评审 | 只交付报告，不修改文件，不进入修正循环 |

没有真实截图或不能操作页面时，明确证据限制，不给实际视觉或交互通过结论。没有隔离执行者时自行检查，并写“未独立评审”。

## 主 Agent 交接材料

给独立评审者：

- 用户原始任务、目标用户、目标视口和硬性约束。
- 当前版本的截图、必要的局部图、序列帧或操作地址，并标注视口。
- 一句设计北极星；存量项目补充必须保留的品牌与组件约束。
- 需要判断的具体范围。

不要给源代码、制作过程的自我辩护、之前评分或期望答案。证据必须属于当前版本；沿用旧证据时注明哪些区域未改变。

宿主支持委派时，让没有本任务制作历史的执行者阅读本文并完成评审。评审者只依据任务、约束和证据，不扩展实现范围。

## 检查顺序

1. 整体构图和阅读起点：主角是否明确，首屏是否服务真实任务。
2. 主动作：入口、可见反馈、对象变化和下一状态是否成立。
3. 内容与可读性：真实文字、长内容、中文换行、数字和字体回退。
4. 层级与一致性：间距、色彩、控件、图标和页面间关系。
5. 状态与设备：空、加载、失败、禁用、窄屏和输入方式。
6. 辨识度与减法：记忆点是否来自产品，是否存在无贡献装饰。

## 报告格式

按影响排序，每条包含：

- 位置：页面、区域、状态与视口。
- 观察：画面中实际看到或操作中实际发生的事实。
- 依据：影响哪个用户目标、设计约束或可用性原则。
- 建议：可执行的调整方向，不写“更高级”一类空词。
- 严重度：`P0` 阻断任务或严重可读性；`P1` 明显影响层级与效率；`P2` 精修。

最后单列“必须保留”的识别点和证据限制。比较候选时分别说明适配与代价，再给选择建议，不先把候选补成自己的方案。

## 处理反馈

第一条若要求重做结构，回到方向卡调整骨架或主视觉，不逐条粉饰。其余按影响从高到低处理。评审建议与用户锁定约束冲突时说明不采纳的理由。出现无可见收益的反复横跳时保留最佳版本并停止循环。
