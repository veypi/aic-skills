# 审美准则（判例式）

来源：video-shotcraft 多支宣传片实战返工的判例沉淀，适配 video_studio/1 浏览器引擎。

**使用方式**：
- 每条 = 规则（一句可执行的话）+ 判例 + 自检问题。
- 终检（`final-review.md`）时逐条过一遍，输出 `编号 ✓` 或 `编号 ✗(位置)`。
- 可以有意识违反（风格需要），但必须写进项目说明（违反了哪条、为什么）。
- 编号体系：R(节奏) / Q(质感·运镜·构图) / S(声音) / C(文案) / P(流程)；只追加不重排。

## 节奏（R）

### R1. 关键信息落定后必须呼吸，品牌字标 hold 满 1 秒
规则：承载信息的元素（字卡/数字/网格全貌）落定后静止 ≥1s 再切镜；呼吸停顿优先给品牌记忆点，不给普通内容卡片。排时间线时预先给 hold/rest 留秒数预算。
判例（shotcraft）：用户两次纠正停留对象——"不是第一个字卡，我说的是开头和结尾的品牌名动画，出现后延长停留1秒"。定案为开头结尾 wordmark 各 hold 满 1 秒。
自检：每个"想让观众记住的画面"有完整静止时刻吗？停顿给的是品牌/关键信息还是随手给了普通元素？
video_studio/1 落地：关键帧末段留平直段（两个同值关键帧拉开 ≥1s）；场景 duration 给足动作+hold。

### R2. 速度感来自加速度，不是匀速快；群体运动挂物理隐喻，收尾留 0.5s 停顿
规则：飞入/滚动一律非线性缓动 + 非均匀错峰，匀速运动读作廉价 PPT；大量同类元素入场用"越来越快"的硬加速节拍（发牌隐喻），满板后静止 0.5s 再切。
判例：抽象 flood 五轮不收敛，换成"发牌式硬加速"一轮通过；用户"归位越来越快……最后停顿0.5秒"。
自检：有元素在做匀速直线运动吗（keyframes easing 全是 linear）？批量入场越来越快吗？末尾有静止呼吸吗？
video_studio/1 落地：批量元素 delay 递减间隔（如 0.5/0.42/0.34/0.26…）+ easeIn 加速段；见 shots/deck-deal-flyin。

### R3. 节奏宁慢勿快：初版默认放慢一档，主体动作弧 ≥3s
规则：开场主体动作（聚焦→推近→悬浮→归位一条完整弧线）至少 3 秒；模拟交互按真人操作速度；第一版几乎总是偏快。
判例：六次独立反馈全部指向"放慢/停留"，从未有一次"太慢了"。
自检：把每个镜头当第一次看，哪里没看清？

### R4. 卡点约束时机不放大幅度：全画面级节拍冲击全片 ≤3 处
规则：强节奏 BGM 片"切点落拍"≠"逐拍打画面"。作用于整画面/相机层的冲击（camera zoom 泵/震屏/白闪帧）全片 ≤3 处、钉 beats.json 最强 onsets、相邻间隔 ≥16 拍；其余拍点只动元素层。
判例：用户"如果给音乐，镜头会随节奏抖动，影响观感"——根因是 kick→冲击被执行成逐拍全画面泵。
自检：数全片 camera shakes + overlay 白闪 + 整画面 scale：超过 3 处了吗？

## 质感·运镜·构图（Q）

### Q1. 复刻既有页面必须真实截图；手搓 UI 限非复刻场景且质量达标
规则：表现产品既有页面时用真实截图素材（browser 技能截图 → 用户上传 assets/），不手搓仿真贴图复刻；抽象开场/品牌段允许手搓 UI 组件，但质感与表达明确性是硬门槛。敏感数据（客户/个人/密钥）必须虚构脱敏。
判例：一下午手搓纹理复刻版整体作废，改用真实页面截图；后修订"可以手搓组件，但要保证质量和表达明确性"。
自检：每块 UI 素材在复刻既有页面吗？是则必须来自截图。

### Q2. 图片素材按显示尺寸 2x 准备；文字发糊先查素材分辨率
规则：image 素材源分辨率 ≥ 显示尺寸 2 倍（运镜推近镜头按推近后的显示尺寸算）；文字模糊先查素材链路，别先动 blur/运镜。
判例：三轮追打"卡片变得模糊了……有像素点的方块"，调景深治标无效，换高分辨率源根治。
自检：zoom 2.3 的特写镜头，素材够 2.3×2 倍吗？截图证据：win(id).shot_video({scale: 2}) 裁剪放大看字边缘。

### Q3. 镜头要稳：默认不加抖动，shakes 只给撞停/重击
规则：camera shakes 是冲击拟音不是氛围抖动——只钉在急推到位/重物落位帧，amp 8–14px、decay ≤0.08s；亮场 UI 片禁止持续抖动。
判例：用户"镜头视角很差，而且有小抖动不知道怎么回事"，去掉 shake 后零投诉。
自检：逐镜头看渲染帧，有没有非叙事意图的抖动？

### Q4. 扫光/高光宁缺毋滥：不群发，一个镜头最多给主角一次
规则：sheen 不做群发——批量元素入场靠运动本身；保留的光效必须被圆角裁剪（引擎自动 overflow+radius）。单点高质量扫光可以做，做完截帧自问"好看吗"。
判例：用户两次否决"不需要每个卡片都闪烁一下""泛光划过的特效取消，不好看"。
自检：数全片 sheen 次数，超过"每镜头主角一次"了吗？

### Q5. 开场只给一个主角：单主体 + 完整动作弧
规则：开场一个主角元素、一条完整弧线（聚光→推近→悬浮→归位），多元素并舞撑不起第一印象。
判例：开场一夜推倒六次，单卡结构定型后直到成片未再动。
自检：开场镜头有几个"想让观众看"的东西？

### Q6. 机位服务可读性：信息密集镜头正视，倾斜逐镜头验证
规则：列表/表格等信息密集镜头保持正视（camera rotation=0）；叙事镜头可倾斜但逐镜头决定；含文字的特写避免大角度旋转破坏可读性。
判例：全片统一倾斜化被否"做的并不好……回滚"，列表页单独恢复正视。
自检：每个 rotation≠0 的镜头，斜的理由是什么？文字还读得清吗？

### Q7. 3D 物件特写四件套：侧机位 + 体积 + 环绕 + 反差背景
规则：three 元素特写做足环境戏——侧斜机位、堆叠出体积、group rotation 环绕动画、与主场景反差的深色背景，拉远同步过渡回主场景。
判例：用户"倾斜从侧面拍摄……镜头围着堆叠做旋转……暗色金属质感背景……然后拉远"。
自检：特写主体有体积感和环境反差吗？相机是死机位还是有运动？

### Q8. 结尾做成"发布会合影"：能量推到全片峰值
规则：多功能产品收尾用全家福——每个已展示功能抽一个代表元素多方向飞入定格围住字标；初版收尾几乎总是偏保守，默认加码一档。
判例：用户"各个页面的核心元素从不同方向飞来……像产品发布"，从合影组装加到发布会级。
自检：结尾是全片能量最高点吗？每个已展示功能都有代表元素吗？

### Q9. 飞入终点必须是布局里的真实槽位
规则：元素飞入后归位到真实格位（keyframes 终点 = 布局坐标），不永久悬浮在页面上方。
判例：用户"不要让10张卡悬浮其上，而是排到下面去，不要重叠"。
自检：每个飞入元素落定后有真实布局坐标吗？

### Q10. 文档类镜头的 mock 内容要出版级
规则：观众会读清屏幕上每个字——文档/报告镜头用原生排版灌满真实密度的假内容，侧栏/页眉完整入镜；"贴图+标语"级假文档整镜头返工。
判例：初版假文档被整镜头重做，最终版原生排版全量 mock、双栏完整入镜。
自检：暂停任意一帧，内容读起来像真的吗？

### Q11. 要被读的文字有最低有效字高：字幕 ≥5% 帧高，辅助 ≥3%
规则：按最终像素量不按 fontSize——有效字高 = fontSize × 全部祖先 scale × 运镜 zoom。720p 字幕 ≥36px（推荐 40px 档）、辅助 ≥22px；1080p 字幕 ≥56px。文字只有两态："纹理"（装饰小字，虚化/降亮度）或"要读"（达标+对比度）；读不到的宁可删。收尾 URL/行动号召是全片最不该小的一行。
判例：六处字幕 25–40px 低于线被整批整改到 60/40/34px 档。
自检：shot_video 截帧缩到 480px 宽（模拟手机小窗），每句还读得清吗？

### Q12. 外框居中不等于视觉居中：按实际文字与主体检查中心线
规则：居中文字同时写 `align:center` 与 `valign:middle`，并让文字框中心 `x+w/2, y+h/2` 与被对齐主体中心一致；多行标题、下划线和说明文字共用一条明确的中心线或左轴线，不靠各不相同的手动缩进制造“居中”。圆点+右对齐文字等复合控件按实际文字起点留间距，不按文本外框左边缘摆圆点。
判例（Lumen）：导出页百分比框虽然水平居中，但默认顶端对齐导致数字偏离圆心；数据页状态点贴着右对齐文本框左边，离实际文字却很远。两者都必须看渲染后的字形位置修正。
自检：圆环内数字真的在圆心吗？多行标题共享轴线吗？状态点、图标与文字看起来是一组吗？

### Q13. 轨道与列表标签逐个绑定真实槽位，禁止用空行撑位置
规则：VIDEO/TEXT/SOUND 等标签拆成独立元素，分别与对应轨道垂直居中；表格、时间轴和卡片列先定槽位中心，再放标签。不要用 `<br><br>`、连续空格或一个高大文本框模拟多行布局，内容高度一改就会错位。
判例（Lumen）：一个文本框用空行排列三个轨道标签，结果 TEXT 落在空白处、SOUND 错对文字轨道；拆成三个独立标签后才与视频/文字/声音三轨一一对应。
自检：每个标签是否都有自己的槽位与中心？隐藏或加高某一轨时，其它标签还能保持正确吗？

## 声音（S）

### S1. 配乐音效按片种选：强鼓点电子底 + 电影系 SFX 词汇，禁游戏音色
规则：SFX 词汇 = whoosh(运镜)/impact(落地)/riser(铺垫)/sparkle(光效)/transition(转场)；禁合成器 bloop/卡通弹跳/game-over 音阶。**禁的是音色不是动作**——画面真有点击/打字就该配真实拟音（快门、键盘、纸张），判别问句：像真实物件的声音还是游戏反馈提示音？
判例：用户"配乐音效太像游戏了……要典型产品宣传视频的音效"，整批替换游戏音包。
自检：闭眼只听音轨，像发布会预告还是手机游戏？

### S2. SFX 逐拍钉帧管理；连发做双样本交替 + 音量阶梯 + 间隔加速
规则：sfx 表每条钉 t + note 注释对应动作；同类连发防机枪感：两个样本交替、音量阶梯递减（0.40→0.25）、间隔跟随动画加速。
判例：六连发 pop 做成音量阶梯 + 间隔 8→3f 加速后通过。
自检：每条 sfx 有 note 吗？连发听起来是节奏还是机械复读？

### S3. 声音在画面锁定后做；时间线一动，SFX 全表重钉
规则：BGM/SFX 排在画面结构锁定后；任何改镜头时长/顺序的修改，收尾固定包含"sfx 表逐条重对 t"。
判例：首版 SFX 钉完 11 小时后画面大改导致全表重钉。
自检：本轮改了时长/顺序吗？sfx 表重对了吗？

### S4. 拟音优先于装饰音；音频裁到与动作严格等长
规则：打字配键盘声、逐条落入配逐个 pop；长样本用 dur/srcOffset 裁剪，泛用 whoosh 盖不住有辨识度的动作。
判例：用户"内容出现时可以配打字音效"，keyboard 按语境裁两个用途。
自检：每个有辨识度的动作有自己的拟音吗？音效拖到动作结束后还在响吗？

### S5. 导出后听一遍成片确认音画同步
规则：浏览器导出管线（WebCodecs AAC/Opus）的音画同步以实测为准——交付前用户试听前，AI 先用 analyze_music 的 onsets 对照 sfx 表钉帧检查逻辑对齐；明显错位（>0.1s）查 t 值与素材峰值滞后（峰值不在文件头的素材用 srcOffset 补）。
自检：sfx 的 t 对的是动作帧还是"大概那里"？

## 文案（C）

### C1. 文案在画面锁定后按最终镜头重写一遍
规则：初稿文案只是占位；画面定稿后对照逐镜头重写；纯动画段落配短解说 caption，不留哑巴段落（品牌收尾除外）。
自检：每句文案和所在画面匹配吗？有超过 3s 的无解说动画段吗？

### C2. 标语写"功能名 + 具体收益"，抽象隐喻词具体化
规则：标语带产品功能名，避免泛化口号；重要功能出场前加引导字卡。
判例：用户逐字改稿，把抽象 board/place 口号换成具体功能名+收益。
自检：每句标语有具体功能名/收益词吗？

### C3. 强调用马克笔 highlight，不靠整句变色
规则：关键词用 span highlight（背景色块+圆角）或下划线描边点睛；整句渐变/整句变色读作廉价。
自检：强调是"一个词"还是"一整句"？

## 流程（P）

### P1. 交付前自己截帧逐一检查，不把首检交给用户
规则：每轮修改后 shot_video 抽关键帧 fs.read 逐张检查（构图/文字锐度/穿帮/越界），再交用户。
判例：用户第一次看片即质问"你自己有截图检查质量吗？"
自检：这一版我自己看过哪些帧？有截图证据吗？

### P2. 参考素材先拆手法清单，再逐镜头判断适配性
规则：有参考片/参考图先列手法清单，按镜头适配性取舍，不全局套用一种风格。
判例：三张参考图被全局套用统一倾斜机位，被否后逐镜头重做。
自检：每个手法有"采用/弃用"的显式决定吗？

### P3. 指代含糊的反馈先确认对象
规则："第一个标题"式模糊反馈先确认所指再动手；改错了干净退回重来，不在错误版本上打补丁。
自检：这条反馈的指代对象我确定吗？

### P4. 先列功能清单逐一对应镜头；一种手法全片只当一次主角
规则：开拍前列功能清单逐一映射镜头，核心功能漏拍等于返工；一种手法（飞入/堆叠/翻页）全片只当一次主角；同一素材/信息全片只出现一次，重复即删。
判例：用户"其他动画有些同质了，没有充分展示整个网站的特性""没有周报部分的展示？"
自检：功能清单每项有镜头吗？有两个镜头用同一手法当主角吗？
