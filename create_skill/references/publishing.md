# 发布手册（本地 → 广场）

> 发布把「本地技能目录」打包为不可变的公开条目，经审核后上架广场。发布不带数据、不带审核信任（内容进入审核）。

## 1. 形态差异速查

| | 本地 | 公开（广场） |
| --- | --- | --- |
| 存储 | `/u/{uid}/skills/{name}/` | `/skills/{id}/`（内容不可变） |
| ref | 目录名 | 注册表 id |
| 页面 URL | `/skills/local/{name}/...` | `/skills/public/{id}/...` |
| 数据 | 本地 sqlite 随改随生效 | 发布不带数据；公开库从空开始 |
| 加载 | `skills load {name}` | `skills load {id}` |
| 更新 | 直接改文件 | 发新版本 |

## 2. 发布流程（/skills 页操作）

1. `/skills` 页 → 「本地」tab → 目标技能 →「管理」→ 「发布」。
2. 选「发布新条目」（name 默认 = 目录名）或「发布到已有条目」（发新版）；设版本号：正则 `^[A-Za-z0-9][A-Za-z0-9._-]{0,15}$`（禁连续点）——建议 `1.0.0` 或日期式 `2026.09.1`。
3. 服务端流式打包本地目录（**不含你的 `.sqlite` 运行库**——在包目录外）。
4. **16MB 闸门**：压缩后超限立即失败，走不到审核。
5. **审核**：全 skill 统一审核（含纯文本；SKILL.md 同样是注入载体）；管理员自发布免审。
6. 通过 = 上架广场（历史版本包留存）；拒绝 = 备注 + 可重提（**版本号须递增**——提交即消耗，被拒也算）。

## 3. 发布前自查（≈ 审核关注点）

- **ui/**：有没有越权调用平台 API（任意 `/api/...`）、偷传数据、来路不明的脚本；有没有写死 `/skills/local/...` 前缀（发布后 scope 变化即失效——用相对路径或运行时派生）。
- **api/**：SQL 是否拼接字符串（禁止）；`user_id = :user_id` 行级过滤是否齐全；全表拉取是否加 LIMIT。
- **文本**：内容合规。
- **通用**：frontmatter 严格 yaml 且名称三重一致；包体积；无调试垃圾（`.bak`、临时文件、大素材）。

## 4. 常见拒绝原因

1. name 与目录名不一致 / 名字不合规（`^[a-z0-9][a-z0-9-_]{0,31}$`）。
2. frontmatter 拼错字段导致解析失败（如 `desc` ≠ `description`）。
3. sqlx 多语句、DDL、拼接 SQL、缺 `:user_id` 过滤。
4. UI 写死本地 scope 前缀（发布后 404）。
5. 包内塞大文件（>16MB）或无关二进制。
6. 内容违规 / 明显调试残留。

## 5. 发布后

- **验证**：换一个账号（或以"无本地目录"的视角）→ `skills search` 找到条目 → `load` 其 id → `open {url_prefix}/index` → `list` + 指令 → `curl` 数据面读回。
- **内容不可变**：任何修改 = 发新版本；`description/nickname/keywords/icon` 随新版本从 frontmatter 刷新（非空覆盖、省略保持现值）。
- **数据不迁移**：公开库从空开始；要带数据就用 owner 管理面（`tables_sqlx`）导出/重建。
- **配额**：正式技能 ≤10/用户；版本号一经提交即消耗（被拒也算）——递增即可。
- **删除条目**：管理页危险区（释放名称与名额；相关绑定级联清理）。

## 6. 试用副本（了解即可）

审核台的「试用」会在**审核员自己的空间**复制一份 `temp_{name}_{版本}` 的本地技能用于真实试用（对方本地 tab 可见），不通过即清理。作者无需操作。
